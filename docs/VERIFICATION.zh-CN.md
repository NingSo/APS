## 本次修改

固定基线的 15 个 `proxycore` 主 Kotlin 文件保持原样。应用模块新建了状态模型、ViewModel、前台服务编排和 Compose 界面。`upstream-lock.json` 记录逐文件来源；本次是新仓库源码导入，不包含完整的上游 Git 历史。

| 部分 | 实现方式 |
| --- | --- |
| 运行状态 | 明确的运行阶段和实际监听配置，偏好开关不等于服务已运行 |
| 会话归属 | 用代次标识隔离服务实例，避免销毁中的旧服务覆盖新状态 |
| 服务生命周期 | 串行命令、真实监听自检、用户启动且不自动粘性重启、partial wake lock、通知停止动作 |
| 重配置 | 保存前提示重建所有监听；端口范围及冲突校验；系统拒绝请求时恢复原偏好 |
| 实时展示 | 基于单调时钟的真实字节增量，每秒采样，最多 60 个点；连接数不冒充设备数 |
| 分享 | 根据当前地址和端口生成文本二维码、实际剪贴板和系统分享；地址改变时使旧分享及确认失效 |
| 授权 | 先确认可信网络，再处理通知权限；通知授权结果不能替代网络信任，返回时再次核对地址 |
| 原生导航 | 三个主入口及设置、诊断；系统安全区；保存页面和编辑状态；仅前台且允许时循环动画 |
| 日志 | 有界内存、INFO/WARN/ERROR 区分；用户确认后导出；不做远程日志 |

内核的错误字段按秒采样，不是完整的逐请求审计流；相同转发错误会去重。本次没有加入鉴权、UDP、设备识别、白名单、云账号或主动外网探测。

## 实际证据与边界

`source-check-report.json` 记录本次确实运行的检查：内核 Git blob 一致性、XML 解析、TOML 版本引用、资源引用、设计颜色、Python 语法，以及针对密钥、生产演示数据和写死网络地址的有限源码扫描。Shell 启动脚本和工作流 YAML 另做了本地语法、结构检查。

**这些都不是 Kotlin 编译。** 单元、集成和原生界面测试已经写入源码，但本次没有运行 Gradle、Android 编译器、模拟器、真机或端到端代理转发测试。环境没有 Android SDK/依赖缓存，容器 DNS 无法解析，且 GitHub 写入被 HTTP 403 拒绝。因此不声称已经完成远端提交、CI 成功、原生截图比对或 APK 构建。

测试覆盖模型校验、会话归属、二维码编解码一致性、速率与采样窗口、配置分享、内核解析及计数、真实本地监听启停和端口占用、风险确认和端口编辑、原生导航及测试截图生成。具体用例方法数见源码检查报告，均明确标记为未执行。

## 发布前必须完成的验收

1. 当前 GitHub 连接取得目标仓库写权限后，同步本地源码；不要强制覆盖已有远端工作。
2. 对该准确提交运行 `Android checks and debug APK`。先解决依赖、编译、Lint 或测试失败，再确认 APK 可构建。
3. 运行 `Native UI tests and screenshots`。将 360dp/412dp 原生输出与设计稿对照，并检查大字体、TalkBack、键盘和安全区。截图数据是明确的测试夹具，不是实际网络验证。
4. 真机安装 Debug APK，从同一可信局域网中的另一台设备验证 HTTP、HTTPS CONNECT、SOCKS5 TCP，访问获得许可的测试目标。不要直接在代理手机上充当客户端，上游回环保护会主动拒绝。
5. 检查改端口的连接中断、两个协议关闭、端口占用、网络丢失和变更、拒绝通知、通知停止、进程终止、反复启动停止，以及导出控制。
6. 检查锁屏、厂商电池策略和所用 VPN 的应用分流组合；本地监听自检及模拟器不能保证这些结果。

正式签名、打版本标签和发布公开 Release 均是独立且尚未执行的操作。包内没有密钥库或复制的凭据。
